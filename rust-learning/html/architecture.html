Inference Pipeline

一次请求从字符串到 next token

  1. 外部输入收束成强类型状态 `Args`、config、prompt、seed、dtype、device。这里处理字符串、文件和网络边界。
  2. token ids 进入 Tensor 世界 `Vec<u32>` 通过 `Tensor::new(..., &device)?.unsqueeze(0)?` 变成 `[B,S]`。
  3. Embedding 输出浮点 hidden 整数 token 只负责查表；进入 block 后主要是浮点 Tensor。
  4. Attention 把 hidden 拆成 heads `[B,S,H] -> [B,N,S,D]`，KV cache 让 decode 阶段的 `S` 和 `T` 分离。
  5. lm_head 产生 logits 只取最后位置 hidden，投影到 vocab，得到 `[B,V]`。
  6. 采样和停止条件推进请求态 `LogitsProcessor` 选 token，生成循环 push token，再检查 EOS。
  7. Tensor op 进入后端 `Tensor::matmul` 检查 shape/dtype/device/layout，再由 `Storage` 分发到 CPU/CUDA/Metal。

Runtime Contracts

四个字段决定大多数错误

shape

维度值只是数字，维度语义才是合同。`[B,N,S,D]` 和 `[B,S,N,D]` 数字相同也不是同一个 Tensor。

dtype

token ids 是索引，hidden/logits 是浮点，量化权重有专门路径。不要靠隐式猜测转换。

device

输入、权重、临时 Tensor 必须在同一运行时设备。新建小 Tensor 时最容易误用 CPU。

layout

`transpose`、`narrow`、`reshape` 可能只是 view；`contiguous()` 才可能触发真实复制。

State Model

模型态、请求态、临时 Tensor 态

模型态

权重、config、layer struct、VarBuilder 路径。可以跨请求共享，加载失败属于启动期错误。

  • 错误关键词：CannotFindTensor、UnexpectedShape
  • 读源码：`vb.pp(...)`、`linear_no_bias(...)`、`Embedding`

请求态

tokens、KV cache、sampler RNG、EOS。必须每个请求独立，不能混进模型单例。

  • 错误关键词：cache 长度、index_pos、随机性不可复现
  • 读源码：generation loop、`Cache`、`LogitsProcessor`

临时 Tensor 态

forward 内部的 hidden、Q/K/V、scores、mask、logits。生命周期短，但错误最多。

  • 错误关键词：shape/dtype/device mismatch
  • 读源码：`Tensor::matmul`、`Storage`、`Layout`

Debug Matrix

遇到错误时先查这张表

症状 第一检查点
ShapeMismatchBinaryOp 打印 rank、batch 维和最后两维，确认 `[B,S,H]`、`[B,N,S,D]`、`[B,N,S,T]`。
DTypeMismatchBinaryOp 确认 token ids、mask、hidden、logits 的 dtype，不要把索引 Tensor 当浮点激活。
DeviceMismatchBinaryOp 检查每个新建 Tensor 是否都用了同一个 `device`，尤其是 mask、position ids、临时 scalar。
CannotFindTensor 从 `vb.pp` 推导完整路径，对照 checkpoint key；权重路径就是模型 ABI。
cached/recompute 不一致 固定 greedy，比较 `S`、`T`、`index_pos`、mask、RoPE offset 和 cache append 维度。
性能突然下降 检查 layout 是否连续，是否在 decode 循环里重复 `contiguous()` 或触发 broadcasted matmul。

Bug Clinic

真实修复：92 个 public API 边界

BUG-001

`replication_pad2d` 原实现只支持 `pad = 0/1`，并且空空间维度下有 `h - 1` 或 `w - 1` 的下溢风险。

BUG-002

`Llama::load` 返回 `Result`，但 block 加载用了 `unwrap()`；缺权重会 panic，而不是返回可定位错误。

BUG-003

`pixel_shuffle` / `pixel_unshuffle` 接收 0 factor 时会除零 panic；修复后返回明确错误，并补 round-trip 测试。

BUG-004

`Cache::append` 在 `max_seq_len = 0` 时扩容步长也是 0，修复前会卡在 while 扩容循环里。

BUG-005

`RotatingCache` 零容量下 `positions` 会取模零，append 和多 token mask 改为返回明确错误。

BUG-006/007

`KvCache` 和 `RotatingKvCache` 改成先更新临时副本，避免 V 失败后 K 已经污染请求态。

BUG-008

`ConcatKvCache::append` 先算 `next_k` / `next_v`，成功后一起提交，保证失败原子性。

BUG-009

`ScatteredCacheBuilder` 显式校验 `batch_mask` 长度，避免短 mask 错形状、长 mask 越界。

BUG-010

ViT patch embedding 在计算 patch 数前拒绝 `patch_size = 0` 和 image/patch 非整除配置。

BUG-011/013

`conv1d`、`conv2d`、`conv_transpose1d` 在权重 shape 计算前校验 `groups`，避免除零和非法分组。

BUG-014/016

ViT、LLaMA2.c 和 Granite 的 head 配置在构造 RoPE 或 attention 前拒绝 0 和不可整除关系。

BUG-017/020

`llama2_c`、Granite、Voxtral loader 去掉 block 加载 `unwrap()`，缺权重返回可定位错误。

BUG-021/023

BatchNorm 拒绝单样本训练态统计，loss 函数在入口处理空 batch 和非法 Huber `delta`。

BUG-024/031

Mimi transformer 在构造期校验 heads、`kv_repeat`、`d_model`，Sin 位置编码避免下溢和 NaN。

BUG-032/037

Gemma4 vision 校验 KV heads、patch/pooling、2D RoPE head dim，并拒绝空 image batch。

BUG-038/044

Gemma4 text 按 layer 类型校验 local/global KV heads 和 head dim，拒绝非法 RoPE factor 与空 token 序列。

BUG-045/053

Gemma4 audio 校验 Conformer heads/chunk、relative position hidden size、SSCP conv 数组和 light conv kernel。

BUG-054/056

Gemma4 multimodal embedding 按 mask true 位置顺序放置，支持多 batch，并拒绝 embedding/token 数量不一致。

BUG-057/059

Gemma4 audio forward 拒绝 mask batch/time 隐式广播和空 time 维，让音频输入合同在入口闭合。

BUG-060/062

Gemma4 继续收紧 multimodal token 数量合同，并拒绝 vision pooling 派生出的 0 输出 token。

BUG-063/069

Qwen3-VL vision 在构造期校验 heads、patch、temporal patch、spatial merge、RoPE head dim 和 position grid。

BUG-070/074

Qwen3-VL text 校验 attention heads、KV heads、GQA 整除关系、head_dim，并在 forward 入口拒绝空序列。

BUG-075/080

Qwen3-VL forward 在入口校验 `seqlens`、`seqlen_offsets` 和 image/video placeholder span，避免 panic 和静默错合同。

BUG-081/086

Qwen3-VL vision 在插值和 reshape 前校验 `grid_thw` 列数、merge 整除关系、token 总数和 grid area 溢出。

BUG-087/092

PaddleOCR-VL vision 在构造期校验 attention heads、RoPE head dim、patch/image size 和 spatial merge。
