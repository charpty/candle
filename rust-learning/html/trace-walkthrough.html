Transcript

prefill 第一轮输出

device: Cpu
prompt token ids: [1, 5, 9, 2]
generation:
  cached prefill: index_pos=0 context_size=4 input_shape=[1, 4]
    token ids [B,S]        shape=[1, 4] dtype=U32
    embedding [B,S,H]      shape=[1, 4, 16] dtype=F32
    attn input [B,S,H]     shape=[1, 4, 16] dtype=F32
    q [B,N,S,D]            shape=[1, 4, 4, 4] dtype=F32
    k cache [B,N,T,D]      shape=[1, 4, 4, 4] dtype=F32
    scores [B,N,S,T]       shape=[1, 4, 4, 4] dtype=F32
    logits [B,V]           shape=[1, 32] dtype=F32
  cached step=00 input=[1, 5, 9, 2] -> token=23 cache_len=4
all token ids: [1, 5, 9, 2, 23]

先看阶段

`cached prefill` 表示第一轮吃完整 prompt。`context_size=4` 来自 prompt 长度。

再看 dtype

token ids 是整数，Embedding 输出后进入浮点世界，logits 采样前保持 F32。

最后看 cache

prefill 后 cache_len 是 4，和 scores 的最后一维 `T=4` 对齐。

Invariants

逐行对应的不变量

stdout 片段 你要读出的系统语义
input_shape=[1, 4] 单请求 batch，当前输入长度是 4。这里还没有进入 Embedding。
token ids dtype=U32 这是索引，不是参与 matmul 的浮点激活。
q shape=[1, 4, 4, 4] 数字上四个 4 很容易误读；真实含义是 `[B,N,S,D]`。
scores shape=[1, 4, 4, 4] 最后一维是 `T`，即 K/V cache 的总长度，不一定等于当前输入 `S`。
logits shape=[1, 32] 只取最后位置 hidden，再投影到 vocab size。生成只需要 `[B,V]`。
cache_len=4 prefill 已经把 4 个 prompt token 的 K/V 放入请求级 cache。

EOS Case

早停输出怎么读

cache comparison:
  cached step=00 input=[1, 5, 9, 2] -> token=23 cache_len=4
  cached step=01 input=[23] -> token=22 cache_len=5
  recompute-all step=00 input=[1, 5, 9, 2] -> token=23 cache_len=4
  recompute-all step=01 input=[1, 5, 9, 2, 23] -> token=22 cache_len=5
  cached generated=2 elapsed=... token/s=...
  recompute-all generated=2 elapsed=... token/s=...
cache comparison result: token sequences match

这段输出证明三件事：cached 和 recompute-all 的 token 序列一致；EOS 命中后两边都早停； 性能统计使用实际生成数 `generated=2`，而不是原始 `sample_len=8`。

Drills

讲完这一页后必须会做的题

为什么 decode 的 input 是 `[23]`，但 recompute-all 是完整上下文？

cached decode 复用历史 K/V，只喂最新 token；recompute-all 每步重算完整 token 序列。

为什么 `Tensor::clone()` 不能等同于复制整块数据？

Candle Tensor 是共享内部对象的句柄，clone 通常复制句柄；真正复制常发生在 `contiguous()`、dtype/device 转换或 host 读取。

如果 EOS 检查放在 `tokens.push` 前，输出语义会怎样变化？

你必须决定是否把 EOS token 放进最终输出。当前 tour 的语义是保留 EOS 后停止。

为什么 `T` 比 `S` 更容易在 cache 代码里出错？

`S` 是当前输入长度，`T` 是 cache 总长度。prefill 时常相等，decode 后通常不同。
